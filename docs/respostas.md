# Respostas às dez questões

1. **Qual problema a aplicação resolve?** Compartilha uma lista de tarefas entre membros de uma equipe conectados a uma rede, evitando listas isoladas em cada computador.
2. **Quem são os processos envolvidos?** Um processo servidor (`servidor.py`) e um ou mais processos clientes (`cliente.py`). As threads de atendimento pertencem ao mesmo processo servidor; não são servidores independentes.
3. **Como ocorre a comunicação?** O servidor escuta em IP/porta conhecidos. O cliente abre uma conexão TCP, envia uma requisição TR/1 e aguarda a resposta. O servidor lê até LF, valida a mensagem, consulta ou modifica o estado e envia um objeto JSON também terminado em LF. O ciclo se repete até QUIT, erro fatal ou desconexão.
4. **Qual transporte foi escolhido?** TCP, usando sockets de fluxo. O servidor é IPv4 e a porta padrão é 5000.
5. **Por que é adequado?** A aplicação depende de entrega ordenada e confiável dos bytes das operações e listas. TCP já oferece retransmissão e ordenação, dispensando a construção desses mecanismos na aplicação. Falhas de conexão continuam sendo possíveis e precisam ser tratadas.
6. **Qual protocolo de aplicação?** TR/1, definido neste projeto: objetos JSON UTF-8 com versão inteira v=1, operações específicas, esquemas de resposta e delimitador LF. Não utiliza HTTP nem depende de navegador.
7. **Quais mensagens podem ser trocadas?** PING/PONG, ADD/resposta com tarefa, LIST/resposta com lista, DONE/resposta com tarefa concluída, QUIT/despedida e respostas de erro com código e mensagem. Os exemplos e todos os códigos estão no README.
8. **O que aconteceria com UDP?** Cada datagrama teria seu próprio limite de mensagem, mas poderia se perder, chegar fora de ordem ou duplicado. Para preservar o comportamento seria necessário acrescentar identificação, ACK, repetição e deduplicação das operações. Uma repetição de ADD sem deduplicação poderia criar duas tarefas. Datagramas grandes também poderiam sofrer fragmentação IP; a aplicação teria que limitar ou dividir as respostas.
9. **Quais erros podem ocorrer?** Servidor ausente, timeout, interrupção da rede, desconexão, porta ocupada, mensagem incompleta/excessiva, codificação/JSON inválidos, versão/operação/campos incorretos, tarefa inexistente, ID/texto inválido e limite de tarefas.
10. **Como são tratados?** Há timeouts, mensagens locais de diagnóstico, validação de esquema e conteúdo, respostas com códigos, fechamento para erro de enquadramento e continuidade para erros semânticos. Uma conexão que falha não interrompe as outras. A trava impede IDs duplicados entre clientes simultâneos. O cliente não repete automaticamente uma operação de resultado incerto.
